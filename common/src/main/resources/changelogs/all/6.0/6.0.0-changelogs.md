## Version Release v6.0.0 MC-1.20.1

### Important
- This version of RunicLib may cause breaking changes with older versions of mods that use this as a dependant (be sure to update!)
  - AZURUNE mods that require this version of RunicLib to fix these issues should be released by the time this version is available
- I decided to name this file RunicLib v6.0 and skip v5.0 since 1.21.1 versions were v5.0 and with 1.21.1 and 1.20.1 being closer in parity it may get confusing with this being v5.0 and 1.21.1 being v6.0

### Breaking Changes
- Updated class name `Services.java` to `RLServices.java`
- Updated class name `RLMobEffects.java` to `RLEffects.java`
- Moved directory `Runiconfig.java`'s directory from `core/runiconfig/` to `core/library/runiconfig/`
- Moved directory `RLToolActions.java`'s directory from `common/util/` to `core/library/misc/`
- Moved directory `RLFurnaceFuelRegistry.java`'s directory from `common/util/` to `core/library/misc/`

### Library Updates
- Added `IAlwaysTickingItem`, a powerful interface for adding ItemStack ticking in different scopes
  - Originally created for a single mod feature of an AZURUNE mod though it's too good to not have within the library itself
  - The documentation for using this can be found in the interface class itself, so read up there if you want to know how to use it
- Runiconfig is now in the .json5 format rather than .json, this means configurations can support comments (`RunicLibConfig.java` for examples)
  -Runiconfig can now support configurations as strings and enum values

### Changes
- Changed the id of the configuration `rlCommandsEnabled` to `runicLibCommands`
- Updated comment in `TickEffectImmuneEffect.java` to mention that the new tags only exist on 1.21+

### Fixes
- Fixed several crashes involving registry freezes on Fabric
